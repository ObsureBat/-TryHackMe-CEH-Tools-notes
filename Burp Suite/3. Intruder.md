# ⚔️ Attack Types (VERY IMPORTANT)

---

## 1️⃣ Sniper ⭐ (MOST USED)

### Concept:

- One payload at a time
    
- Each position tested separately
    

```
Requests = payloads × positions
```

### Example:

```
username=burp&password=123
username=admin&password=123
...
```

---

## 2️⃣ Battering Ram

### Concept:

- Same payload in all positions
    

```
username=admin&password=admin
```

---

## 3️⃣ Pitchfork

### Concept:

- Multiple payload sets (parallel)
    

```
username=joel&password=J03l
username=alex&password=Sk1ll
```

👉 Used for:

- Credential stuffing
    

---

## 4️⃣ Cluster Bomb ⭐

### Concept:

- All combinations
    

```
Requests = set1 × set2 × set3...
```

---

## 🧠 Attack Type Summary

|Type|Payload Sets|Behavior|
|---|---|---|
|Sniper|1|One-by-one|
|Battering Ram|1|Same everywhere|
|Pitchfork|Multiple|Parallel|
|Cluster Bomb|Multiple|All combinations|

---

# 📊 Request Calculation

### Sniper:

```
Requests = words × positions
```

### Cluster Bomb:

```
Requests = multiply all payload sets
```

# 🧪 Practical Attack 1: Credential Stuffing

---

## 🎯 Target:

```
/support/login
```

---

## 🧠 Strategy:

- Use leaked credentials
    

---

## ⚙️ Steps:

1. Capture login request
    
2. Send to Intruder (`Ctrl + I`)
    
3. Select positions:
    

```
username
password
```

4. Attack Type:
    

```
Pitchfork
```

---

## 📦 Load Payloads:

- usernames.txt
    
- passwords.txt
    

---

## ▶️ Run Attack

---

## 🔍 Identify Success:

- Status code same → 302
    
- Use:
    

```
Sort by Length
```

👉 Shorter response = SUCCESS

---

## 🔥 Attack Flow

```
Wordlists → Inject → Send → Compare Response Length → Find Valid Login
```

# 💉 Advanced Attack: CSRF Token Bypass (Macro)

---

## ⚠️ Problem:

- Dynamic values:
    
    - session cookie
        
    - loginToken
        

---

## 🧠 Solution:

- Use **Burp Macros**
    

---

## 🔄 Flow:

```
Request → Run Macro → Get Token → Inject → Send Attack
```

---

---

- Settings → Sessions → Macros → Add
    

---

### Step 3:

- Create Session Handling Rule
    

---

### Step 4:

Update only:

```
loginToken
session
```

---

- Attack Type → Pitchfork
    
- Positions → username + password
    

---

## 🔍 Result:

- Shortest → valid login
